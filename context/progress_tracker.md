- **Out-of-sequence bug-fix session (2026-08-12), two real-device-only mobile bugs — resolved.** Reported by the user testing on a physical Android/Chrome device (not reproducible on desktop or in DevTools mobile emulation): (1) sticky Nav desyncing during scroll (behaved like a normal in-flow element scrolling away, only "reattaching" on a scroll-direction reversal); (2) a small horizontal overflow (white gutter on one side + a horizontal scrollbar) with the page loading visibly zoomed out. Full root-cause path, in order investigated (see git history on `main` for the individual commits, all with detailed messages):
  - Two hypotheses tried and **reverted as ineffective** (do not re-attempt without new evidence): `hero.tsx` `100dvh` → `100svh` (removes toolbar-driven reflow next to the sticky Nav), and a persistent invisible `position: fixed` element in the root layout (documented Chromium workaround for sticky/fixed tracking during toolbar resize). Pushed to `main`, tested on-device, **did not fix either symptom** — reverted via `git revert` (commit `dc8339c`). Branch `fix/mobile-sticky-nav` (which held this attempt) has since been deleted, both locally and on `origin`.
  - **Real fix #1** — `app/[locale]/layout.tsx` (`bb000d2`): Next.js 16.3's auto-generated viewport meta tag, verified via `curl` against real build output, only emitted `<meta name="viewport" content="width=device-width">` — missing `initial-scale=1`, despite the framework's own docs claiming the default is sufficient. Added an explicit `export const viewport: Viewport = { width: "device-width", initialScale: 1 }`. Deliberately omitted `maximumScale`/`userScalable` (Next's own "full" recommended default sets `user-scalable=no`, a WCAG 1.4.4 violation).
  - **Real fix #2 — the actual root cause of both symptoms** — `components/certificates-list.tsx` (`daf7ee5`): a certificate label (`"Software Engineering: Modeling Software Systems using UML"`, 58 chars) was rendered with `whitespace-nowrap` inside a `flex` button with no `min-w-0` — a flex item's default `min-width: auto` never shrinks below its unwrapped content width, so this button (and therefore the whole document, since no ancestor anywhere in the tree has `overflow-hidden`) rendered wider than the real device width on narrow mobile viewports. A page wider than its declared viewport is the documented cause of Chrome's initial zoomed-out render (explaining the white gutter/scrollbar) and, per MDN, can also throw off `position: sticky` (which resolves against the layout viewport, not the visual one) — a single root cause for both reported bugs. Fixed with `min-w-0` on the flex container + `truncate` (replacing `whitespace-nowrap`) on the label span; full text remains available via the button's existing `aria-label` and by opening the certificate lightbox. **User-confirmed on the real device after deploy: both bugs resolved.**
